# 临床数据工程专家：人物画像与任务说明

---

## 一、要找什么样的人

### 核心画像

**一位真正用公开 ICU 数据库（MIMIC / eICU）从原始表里构建过研究队列的人。**

关键词是"**真正构建过**"——不是跑过别人的 notebook，不是用过已经处理好的数据集，而是自己从 `chartevents`、`labevents` 这些原始表里把变量抽出来、对齐过口径、处理过单位不一致。

具体可以是以下任一种：

| 类型 | 具体要求 |
|---|---|
| 医学信息学 / 生物医学工程方向研究生或博士后 | 做过 MIMIC/eICU 相关课题，自己写过取数 SQL |
| 临床大数据 / 医疗 AI 实验室的研究人员 | 做过多中心数据整合 |
| 医院信息科的科研数据平台工程师 | 做过临床数据仓库或 CDR 建设 |
| 做过 OMOP CDM 映射的人 | 直接对口，这就是同一类工作 |

### 必须具备

1. **知道各张表分别装什么。** `chartevents`（床旁记录）、`labevents`（化验）、`inputevents`（给药）、`prescriptions`（处方）、eICU 的 `nurseCharting` / `vitalPeriodic` / `infusionDrug` / `customLab`。
2. **有跨库口径对齐的经验。** 知道同一个临床变量在不同库里字段名、单位、记录频率、记录方式都不同。
3. **看得懂英文字段名和医学缩写。**

### 加分项

- 用过 `ricu`、`mimic-code` 或 OMOP CDM 中的任意一种概念映射工具
- 处理过单位不一致（mEq/L vs mmol/L、mg/dL vs μmol/L）
- 做过多中心数据的迁移或泛化实验

### 不需要具备

- **不需要**临床执业背景
- **不需要**有医学学位

### 这个人为什么合适

我们要判断的问题里有很大一部分是 **schema 层面的同一性**，需要对数据库结构本身的理解：

- 处方表里的"去甲肾上腺素"（医嘱开了）和给药表里的"去甲肾上腺素"（实际泵入）不是同一个变量
- eICU 的 `customLab` 是各站点自定义的化验项，映射不到任何统一概念
- eICU 根本没有 `param_type` 这一列，所以类型信息在那个库里是缺失的，不能当作"类型不匹配"
- 某个字段每住次记录 1000 多条、中位数 80——不用看名字也知道是床旁连续监测的心率或血压

这些判断，一个做过队列构建的人很清楚；一个纯临床背景的人反而可能不熟悉。

### 在哪里找

- 高校的医学信息学、生物医学工程、公共卫生大数据方向的实验室
- 做临床 AI 的研究组（尤其做过 ICU 预测模型的）
- 医院信息中心 / 数据中心做过科研数据平台的工程师
- 发表过 MIMIC / eICU 相关论文的国内作者
- OHDSI 中国社区

## 二、这个人具体要做什么

### 一句话

**填一张 198 行的表格。每行是一个 ICU 数据库字段的元信息，判断它应该映射到 138 个统一概念中的哪一个；映射不上就写 UNKNOWN。**

### 拿到的材料

一个压缩包，里面有三样东西：

1. `标注表_数据工程专家.xlsx` —— 要填的表，198 行（同时提供 CSV 版）
2. `概念清单.csv` —— 138 个目标概念（Excel 版里是第二个工作表）
3. `填写说明.md` —— 详细的填写规则

### 表格长什么样

每行给出该字段的全部可用元数据：

| 列 | 内容 |
|---|---|
| 来源库 / 来源表 | MIMIC-IV、MIMIC-III (CareVue)、eICU-CRD，以及具体哪张表 |
| 字段名 / 缩写 | 原库里的原文 |
| 原库字典分类 | |
| 声明的数据类型 | **空 = 该库根本没有这一列**（eICU 就是这样） |
| 标本类型 | **空 = 该库没有这一列** |
| 实测单位 | 从数据里恢复的众数单位，**空 = 该字段没有任何单位记录** |
| 取值 1% / 50% / 99% 分位数 | |
| 覆盖率 / 每住次记录条数 | 常常比名字更能说明问题 |

### 要填的三列

1. **答案**：从概念清单里选（Excel 有下拉菜单）/ `UNKNOWN` / `UNSURE`
2. **置信度**：1–5
3. **备注**：有话才写，一句话

### 判断时的五条规则

1. **看单位与取值范围，不要只看名字。** 覆盖率和每住次记录条数经常能直接定性。
2. **来源表决定语义。** 处方表 vs 给药表；护理记录表 vs 周期性生命体征表。
3. **标本类型不同 → 不同概念。**
4. **测量方式不同 → 不同概念。** 有创 vs 无创血压；呼吸机设定值 vs 实测值；床旁快速血糖 vs 实验室血糖。
5. **站点自定义项、设备型号、护理评估量表、文本标志位** 基本都是 `UNKNOWN`，除非清单里确有对应项。

### 工作量

**约 1.5 到 2 小时**，可分次完成。

### 两条硬性要求

1. **独立完成。** 另有一位标注者在做同一份表，两人不要讨论、不要对答案。我们需要的正是两份互不影响的判断。
2. **不要用 AI 代填。** 这份标注的全部价值就在于它不是模型给出的——用 AI 填等于让整件事作废。

### 关于数据

表格里只有字段级元信息，**不含任何患者数据**，不涉及隐私或伦理审批。

### 交回方式

填好的表格原样发回，**不要改动前面那些列或行的顺序**——靠行号对齐。

### 署名

如果这份标注被采用，会在论文致谢中署名；如果本人希望，也可以列为共同作者。

## 三、这件事是干什么用的（可以告诉候选人）

我们在做一项跨 ICU 数据库字段自动对齐的研究。目前这套自动方法的正确性是由**另一套程序**判定的，构成循环论证。我们需要一份**由人做出的、独立的判定**来检验它。

**重要背景**：三个库的字段总数远多于 138 个统一概念，所以**大部分字段本来就映射不上**。我们要量化的正是这一点——所以 `UNKNOWN` 是一个正常且频繁的正确答案（这 198 行里约四成半是这种情况），不是失败，也不是没做出来。

抽样是有针对性的，重点落在最容易出错的地方：判为 UNKNOWN 的高覆盖字段、只有弱证据支持的映射、两次判定有分歧的、以及单位/类型/标本存在冲突的。所以这份表比随机抽的 198 行要难。
